# 디펜스 준비

## Mandatory Part

### 프로젝트 개요

---

- 가상 머신의 작동 방식
    - 가상머신은 물리적 컴퓨터와 동일한 기능을 제공하는 소프트웨어 컴퓨터이다.
    - 물리적 컴퓨터처럼 애플리케이션과 운영체제를 실행한다.
    - 하이퍼 바이저를 이용한 가상화 기술로 가상환경과 시스템을 공유하도록 허용해준다(하이퍼바이저: 하드웨어를 관리하고 물리적 자원들을 가상환경으로 부터 분리한다.). 하이퍼바이저의 유형에 따라서 작동방식이 두가지로 나뉘는데, Type1은 가상환경의 자원이 하드웨어에 직접 연결된다. Type2는 가상환경의 자원이 시스템 OS에 연결된다. 현재 사용하는 버추얼 박스는 Type2이다.
- 운영 체제 선택
    - Debian을 선택하였다.
        - Debian 프로젝트가 개발한 자유 운영체제이다.
        - 패키지 설치 및 업그레이드의 단순함이 특징이다. (APT방식이용)
- Rocky와 Debian의 기본적인 차이점
    - **Based on**
        
        Debian: 데비안 프로젝트라는 커뮤니티 개발
        
        Rocky: 레드햇 RHEL(red hat enterprise linux) 기반
        
    - **Security Framework**
        
        Debian: apparmor 사용
        
        - Apparmor는 프로세스별로 보안 프로파일을 생성 → 각 애플리케이션의 액세스 제한 → **프로필 기반 시스템**으로 구현
        
        Rocky: SELinux 사용
        
        - SELinux는 시스템 전체에서 사용되는 보안 모듈 → 일반적으로 **규칙 기반 시스템**으로 구현
        - DAC(임의 접근 통제) → 소유자는 자신의 판단에 의해서 권한을 줄 수 있다는 의미이며 구현이 용이하고 사용이 간편 but, 사용자의 권한을 탈취당하면 사용자가 소유하고 있는 모든 객체의 접근 권한을 가질 수 있게 되는 치명적인 문제가 있다.
    - **Package Manager**
        
        의존성: 한 프로그램을 설치할 때 라이브러리나 프로그램이 필요한 것.
        
        Debian: apt
        
        Rocky: DNF - libsolv를 통해 의존성 문제를 처리한다.
        
- 가상 머신의 목적
    - 호스트 환경에서 수행하기 힘든 작업들을 해야할 때 (바이러스등)
    - 서버용 컴퓨터를 보다 효율적으로 사용할 수 있을 때
- 평가 대상 학생이 데비안을 선택한 경우:
    - APT와 Aptitude의 차이
        - APT는 low-level package manager, Aptitude는 high-level package manager이다.
        - APT는 그래픽 인터페이스가 없고, 명령어로 사용한다.
        - Aptitude는 사용자 인터페이스를 추가하고, 대화형으로 패키지를 검색해 설치한다.
        - Aptitude가 더 방대하고, apt-get, apt-cache 기능을 포함한다.
        - APT는 설치, 제거 중 충돌이 일어날 경우 종료, Aptitude는 해결방법을 제시할 수 있다.
    - Apparmor가 무엇인지
        - 리눅스 보안 애플리케이션 시스템이다.
        - root 보다 상위권한으로 모든 행동을 제어한다.
        - MAC(강제적 접근 통제를 제공한다.)
            - 객체의 소유자라고 해도, 보안정책에 어긋나면 객체에 접근할 수 없다.
            - 관리자만이 객체의 보안레벨, 주체의 보안등급을 수정 가능하다.
            - 높은 보안을 요구하는 정보는 낮은 보안 수준의 주체가 접근할 수 없다.
    - 방어하는 동안 10분마다 정보 표시가 되는지
        - 다음 평가 항목에서 버추얼박스 실행하면서 진행하면서 보자고 말하자. Monitoring.sh 잘 만들었으면 자동으로 나옴

### 간단한 설정

---

- 시작 시 머신에 그래픽 환경이 없는지 확인하십시오. 평가 학생의 도움을 받아 사용자와 연결합니다. 이 사용자는 루트가 아니어야 합니다.
    - 그냥 버추얼 박스 실행시켜서 본인걸로 로그인 하면된다.
- 평가자의 도움을 받아 UFW 서비스가 시작되었는지 확인합니다.
    - **`$ systemctl status ufw`**
- 평가자의 도움을 받아 SSH 서비스가 시작되었는지 확인합니다.
    - **`$ systemctl status ssh`**
- 평가자의 도움을 받아 선택한 운영체제가 Debian 또는 Rocky인지 확인하세요.
    - **`$ lsb_release -a`**
        - **`-a`**: show all infromation

### 사용자

---

- 평가 중인 학생의 로그인 정보를 가진 사용자가 가상 머신에 존재하도록 요청합니다. 추가되었는지, “sudo” 및 “user42” 그룹에 속해 있는지 확인하세요.
    - **`$ groups wonyocho`**

다음 단계에 따라 비밀번호 정책과 관련된 주제에 부과된 규칙이 적용되었는지 확인하십시오.

- 먼저 새 사용자를 만듭니다. 주제규칙을 준수하면서 원하는 비밀번호를 지정하세요. 평가 대상 학생은 이제 가상 머신에서 해당 주제에 대해 요청된 규칙을 어떻게 설정할 수 잇었는지 설명해야 합니다. 일반적으로 수정된 파일은 하나 또는 두개 있어야 합니다.
    - **`$ adduser <username>`**
    - **`$ cat /etc/passwd`** → user 확인
    - `libpam-pwquality` → password 강도를 확인할 수 있는 모듈 설치를 해주었다고 말하기.
    - **`$vi /etc/pam.d/common-password`**
        - minlen=10: 비밀번호가 최소 10자리
        - difok=7: 비밀번호 변경시, 이전 비밀번호와 최소 7개는 다르도록 해야함
        - ucredit =-1: 대문자 알파벳 최소 1개 포함
        - lcredit=-1: 소문자 알파벳 최소 1개 포함
        - dcredit=-1: 숫자 최소 1개 포함
        - reject_username: 사용자 이름과 유사한 패드워드 사용하지 못하게 함
        - enforce_for_root: 루트 계정에 대해서도 이 규칙을 강제하도록 설정
        - maxrepeat=3: 같은 문자나 숫자 3번까지만 반복
    - **`$ sudo vi /etc/login.defs`** → ****password 기간 수정 파일
- 새 사용자가 생겼으므로, “evaluating”이라는 그룹을 만들고 이 사용자를 할당하도록 요청하세요. 마지막으로, 이 사용자가 “평가 중”그룹에 속해 있는지 확인하세요.
    - **`$ groupadd <groupname>` →** 그룹추가
    - **`$ gpasswd -a <username> <groupname>` →** 그룹에 유저 추가
        - **`-a` :** add user to group
    - **`$ groups <username>` →** 확인
- 마지막으로 평가 대상 학생에게 이 비밀번호 정책의 장점과 구현의 장점과 단점을 설명하도록 요청하세요. 물론, 피험자가 요구하기 때문이라고 대답하는 것은 포함되지 않습니다.
    - 장점: 그냥 뭐 보안이 강해진다.
    - 단점: 너무 까다롭게 이렇게 해놓으면 사용자 본인이 까먹을 수 있다.

### 호스트 이름 및 파티션

---

- 머신의 호스트 이름이 login42와 같이 올바른 형식인지 확인하십시오.
    - **`$ hostnamectl`**
- 로그인을 자신의 로그인으로 바꿔서 이 호스트 이름을 수정한 다음 컴퓨터를 다시 시작하세요. 다시 시작할 때 호스트 이름이 업데이트되지 않은 경우 여기에서 평가가 중지됩니다.
    - **`$ sudo hostnamectl set-hostname [바꿀호스트네임]`**
- 이제 머신을 원래 호스트 이름으로 복원할 수 있습니다.
    - **`$ sudo hostnamectl set-hostname [바꿀호스트네임]`**
- 평가받는 학생에게 이 가상 머신의 파티션을 보는 방법을 물어보세요.
    - **`$ lsblk`**
        - / : root, 모든 파일의 최상단
        - root : 시스템 관리자의 홈 디렉토리 (일반 사용자 접근 불가능)
        - boot : 부팅에 필요한 이미지 파일/부팅 정보 가진 디렉토리
        - home : 사용자 디렉토리 저장
        - var : 로그 파일, 캐시 등 가변적인 데이터를 저장하는 디렉토리
            - var/log: 시스템 로그 파일을 저장하는 디렉토리
        - srv : 서버를 위한 디렉토리 (시스템에게 제공되는 파일 저장)
        - tmp : 임시 파일 들어있는 디렉터리, 부팅시 초기화
        - swap : ram이 가득 차 공간 부족시 예비 공간 역할
        - var 과 tmp의 차이 → var은 시스템 동작중에도 지속적으로 유지되지만 tmp는 시스템이 주기적으로 관리하는 특징이 있다.
- 출력을 주제에 제공된 예와 비교하십시오. 참고: 평가 대상 학생이 보너스를 받는 경우 보너스 예시를 참고해야 합니다.
    - 나는 파티션만 보너스 형식대로 나누었다. 보너스 해볼려다가 그냥 안해서. 2점만 주시믄 댄다.
- 평가를 받는 학생은 LVM의 작동 방식과 LVM의 내용에 대해서 간략하게 설명해야 합니다. 예상대로 작동하지 않거나 명확하게 설명되지 않는 경우 평가는 여기서 중지됩니다.

    - LVM: 리눅스의 저장공간을 효율적이고 유연하게 관리하기 위한 커널의 한 부분이다.
    - VG(volume group)에서 원하는 대로 쪼개서 LV를 만든다.
    - 장점: 유연한 용량조절, 편의에 따른 장치 이름 조정
    - 단점: 데이터 복구가 어려울 수 있다.
    - 100GB를 50GB/50GB로 나눈다음, 지점토를 떼서 붙이듯이 용량을 확장할 수 있다.

### Sudo

---

- 가상 머신에 “sudo”프로그램이 제대로 설치 되어 있는지 확인하세요.
    - **`$ dpkg -l | grep ‘sudo’`**
        - **`dpkg` :** `dpkg`는 데비안 패키지 관리 시스템의 기초가 되는 소프트웨어로서, `.deb` 패키지의 설치, 삭제, 정보 제공을 위해 사용되는 명령어이다.
- 이제 평가 중인 학생은 새 사용자를 “sudo” 그룹에 할당하는 모습을 보여야 합니다.
    - **`$ usermod -aG sudo <username>`**
        - usermod: 사용자 계정을 수정하는 명령어
        - -a: 기존의 그룹은 유지하고 새로운 그룹을 추가하는 옵션
        - -G: 사용자가 속할 그룹을 설정
- 주제는 sudo에 대한 엄격한 규칙을 적용합니다. 평가 대상 학생은 먼저 자신이 선택한 예를 사용하여 sudo의 가치와 작동을 설명해야 합니다. 두 번째 단계에서는 주제에 의해 부과된 규칙의 구현을 보여주어야 합니다.
    - **`$ visudo` 설명하기**
        
        ![Screen Shot 2024-01-03 at 2.21.50 PM.png](%E1%84%83%E1%85%B5%E1%84%91%E1%85%A6%E1%86%AB%E1%84%89%E1%85%B3%20%E1%84%8C%E1%85%AE%E1%86%AB%E1%84%87%E1%85%B5%20d54db7e4d8df444fb493e32b0d94981d/Screen_Shot_2024-01-03_at_2.21.50_PM.png)
        
        - env_reset: 사용자가 sudo를 통해 명령을 실행할 때, 환경 변수를 재설정한다. 보안측면에서 환경 변수를 통한 공격을 방지하기 위한 조치이다.
        - mail_badpass: 사용자가 비밀번호를 잘못 입력 했을 때 관리자에게 경고 이메일을 보낸다.
        - secure_path: 환경 변수 $PATH를 sudo 실행 시 재설정하는 대신, 명시적으로 지정된 안전한 경로를 사용한다. 보안측면에서 중요하다. 특히 트로이 목마 공격의 1차적 방어를 해준다.
        - authfail_message: 인증에 실패할 때 사용자에게 보여줄 메세지를 설정한다.
        - badpass_message: 비밀번호가 잘못 입력되었을 때 사용자에게 보여줄 메시지를 설정한다.
        - log_input / log_output: sudo로 실행한 명령의 입력과 출력을 로그에 기록한다.
        - requiretty: sudo로 명령을 실행할 때, tty(터미널)가 필요한지 여부를 지정한다.
        - iolog_dir=”/var/log/sudo”: sudo 명령의 입력과 출력을 저장할 디렉토리를 지정한다. 디렉토리가 존재 하지 않으면 생성된다.
        - passwd_tries: 사용자가 비밀번호를 잘못 입력할 수 있는 횟수를 제한한다.
    - 먼저, sudo는 root가 아닌 사용자가 root에 준하는 실행능력을 갖게 해주는 명령어이다.
    - 예시로, 방금 했던 것 처럼 sudo그룹에 추가할 때 반드시 sudo를 추가해주어야 한다.
- “/var/log/sudo” 폴더가 존재하고 하나 이상의 파일이 있는지 확인 하십시오. 이 폴더에 있는 파일의 내용을 확인하면 sudo와 함께 사용된 명령 기록이 표시됩니다. 마지막으로 sudo를 통해 명령을 실행해 보세요. “/var/log/sudo” 폴더의 파일이 업데이트되었는지 확인하세요. 예상대로 작동하지 않거나 명확하게 설명되지 않는 경우 평가는 여기서 종료됩니다.
    - **`$ cd /var/log/sudo/00/00/01`**→ **`$ cat log`** 로 로그 확인 할 수 있다.

### UFW / Firewall

---

- “UFW” 프로그램이 가상머신에 제대로 설치되어 있는지 확인하세요.
    - **`$ sudo ufw status`**
- 제대로 작동하는지 확인하세요.
    - **`$ sudo ufw status`**
- 평가받는 학생은 기본적으로 UFW가 무엇인지, 그리고 이를 사용하는 가치에 대해 설명해야 합니다.
    - UFW(Uncomplicated FireWall)로, 말그대로 데비안 계열 및 리눅스 환경에서 작동하는 사용하기 쉬운 방화벽 관리 프로그램이다. (명령줄이 간단)
    - PC와의 통신시, 임의의 입구, ‘포트’를 할당 받는다. 해당 포트를 통해 들어오고, 나가며 정해진 동작을 수행한다. 여기서, 우리는 방화벽 설정을 통해 어떤 포트를 원하는 대상에게 개방/폐쇄 할 수 있다.
    - 포트: 네트워크 상에서 통신하기 위해 호스트 내부적으로 프로세스가 할당 받아야 하는 고유한 숫자이다. 즉, 같은 컴퓨터 내에서 프로그램을 식별하는 번호이다.
- UFW의 활성 규칙을 나열합니다. 포트 4242에 대한 규칙이 있어야 합니다.
    - **`$ sudo ufw status`** or **`$ sudo ufw status numbered`**
    - v6: ip버전

    - **`$ sudo ufw status` →** 확인
- 마지막으로 평가 대상 학생의 도움을 받아 이 새 규칙을 삭제하세요. 예상대로 작동하지 않거나 명확하게 설명되지 않은 경우 평가는 여기서 중지 됩니다.

    - **`$ sudo ufw delete [줄 번호]`**

### 스크립트 모니터링

---

- 코드를 보여줌으로써 스크립트가 작동하는 방식
    
    **`#Architecture`**: 운영체제와 커널의 버전에 대한 구조
    
    - `uname`: 시스템 정보 출력 명령어
        - `-a`: 커널 이름, 네트워크 호스트명, 커널 릴리즈 정보, 커널 버전, 시스템의 하드웨어 타입(아키텍쳐), 운영체제 이름을 출력한다.
    
    *운영체제: 사용자의 하드웨어, 시스템 자원을 제어하고 프로그램에 대한 일반적인 서비스를 지원하는 시스템 소프트 웨어
    
    *커널: 컴퓨터 운영체제의 핵심이 되는 컴퓨터 프로그램. 응용 소프트웨어(애플리케이션)을 하드웨어와 연결한다.
    
    *아키텍쳐: 컴퓨터 시스템의 하드웨어 구조를 말한다. CPU, 레지스터, 기억장치 등과 같은 여러가지 컴퓨터 구성요소들에 대한 전반적인 기계적 구조와 이를 설계하는 방법을 말한다.
    
    **`#CPU physical`**: 물리 프로세서들의 수
    
    - `nproc --all`: 설치된 모든 코어 / 프로세스 수 출력
    
    *프로세서: 컴퓨터 운영을 위해 기본적인 명령어들을 처리하고 반응하기 위한 논리회로이다.
    
    *코어: 프로세서가 하는 일을 분담해주는 장치
    
    **`#vCPU`**: 가상 프로세서들의 수
    
    - `/proc/cpuinfo`: CPU 정보가 담겨있는 파일
    - `cat /proc/cpuinfo | grep processor | wc -l`: CPU 정보가 담겨 있는 파일 중 프로세스만 찾아 개수를 출력
    
    *가상 프로세서: 공유 프로세서를 사용하는 논리 파티션의 운영체제에 대한 물리적 프로세서 코어의 표현.
    
    **`#Memory Usage`**: 현재 서버에서 사용가능한 RAM과 백분율로 표현된 사용률
    
    - `free`: 시스템 메모리 사용 현황 출력 명령어
        - `m`: 메가바이트 단위로 표시
    - $ →  특수변수
    - `$2`: memory total `$3`: memory used
    
    **`#DiskUsage`**: ****현재서버에서 사용가능한 memory와 백분율로 표현된 사용률
    
    - `df`: 파일시스템 디스크 공간의 사용량을 출력하는 명령어
        - `a`: 0 블록의 파일시스템을 포함해 모든 파일시스템을 출력하는 옵션
        - `B`: 지정한 크기(SIZE)를 블록단위로 정하여 용량 표시하는 옵션
        - `BM`: 크기를 1M으로 블록단위를 정해 용량을 표시
        - $3: 사용한 메모리 용량 $4: 남은 메모리 용량
    
    **`#CPU load`**: 백분율로 표현된 프로세서들의 현재 사용률
    
    - `mpstat`: 사용가능한 CPU와 Core 별 사용량을 출력하는 명령어 (`sysstat` 설치 필요)
    - $13: CPU 사용률
    
    **`#Last boot`**: 마지막으로 재시작된 날짜와 시간
    
    - `who`: 호스트에 로그인한 사용자 정보 출력
        - `b`: 마지막 시스템 부팅 시간을 출력하는 옵션
    
    **`#LVM use`**: `lsblk | grep 'lvm' | wc -l | awk '{if($1>0)print"yes";else print"no"}'`
    
    - 파티션 정보를 출력하는 **lsblk**에서 타입이 **lvm**인 부분을 추출한 뒤 라인 수를 구하고 그것이 0 이상이라면 파티셔닝이 된것이니 yes를 출력하게하고 0보다 작다면 no를 출력
    
    **`#Connectios TCP`**: 활성화된 연결들의 개수
    
    - TCP: 컴퓨터 네트워크에서 데이터를 안정적으로 전송하기 위해 사용되는 프로토콜 중 하나.
    - `ss`: 소켓 상태를 조회할 수 있는 유틸리티로 `netstat`와 비슷한 역할을 수행한다.
    - `grep -i`: 대소문자구별하지않고 가져옴
    
    *소켓: 프로세서가 네트워크로 데이터를 내보내거나 혹은 데이터를 받기 위한 청구이다.
    
    **`#Userlog`**: 서버를 사용하고 있는 유저의 수
    
    - `who`: 호스트에 로그인한 사용자 정보 출력
    
    **`#Network`**: 서버의 IPv4 주소와 MAC 주소 IP
    
    - `hostname`: 시스템 이름을 확인하고 설정하는 명령어
        - `I`: 호스트의 IP 주소를 출력하는 옵션
    - `ip`: IP 유틸리티는 모든 최신 Linux 배포 환경에 설치된 iproroute2 패키지의 일부로, 인터페이스를 위/아래로 가져오고, 주소와 경로를 할당 및 제거하고, ARP 캐시를 관리하는 등 다양한 용도로 사용된다.
        - `link`: 네트워크 인터페이스를 표시하고 수정한다.
        - `show`: 관련 인터페이스 출력한다.
    - **`ip link show`:** 시스템의 네트워크 인터페이스 정보를 출력한다.
    - **`awk ~~~~ %2}’`** : 출력된 정보중에서 첫 번째 열이 link/ether 인 행을 선택하고, 그 행에서 두번째 열의 값을 출력한다. 이는 MAC주소 이다.
    - **`‘sed ‘2, $d’`**: 선택된 MAC 주소중에서 두번째 행 이후의 모든 행을 삭제한다.
    
    *arp캐시: IP주소와 MAC주소 사이를 연결해 주는 기능.
    
    **`#Sudo`:** sudo 프로그램으로 실행된 명령의 수
    
    - `journalctl`: `systemd`의 서비스 로그를 확인할 수 있으며, `systemd-journald.service`에 의해서 `systemd`의 정보들을 분석한다.
        - `systemd`: 일부 리눅스 배포판에서 '유닉스 시스템 V'나 'BSD init 시스템' 대신 사용자 공간을 부트스트래핑하고 최종적으로 모든 프로세스들을 관리하는 init 시스템
        - `_COMM=sudo`: 특정로그(sudo) 보기
        - `grep “COMMAND=”` : **`sudo`** 명령어의 로그는 **`COMMAND=`** 문자열을 포함하고 있어서, 이를 통해 **`sudo`** 명령의 실행된 명령어만을 추출한다. 이는 다른 시스템 로그와의 혼동을 방지하고 정확한 **`sudo`** 명령의 실행 횟수를 세기 위한 것이다.
- “크론”이 무엇인가요?
    - cron: 리눅스에서 제공하는 스케줄링 도구.
    - 정기적으로 반복되는 작업을 자동으로 수행하도록 스케쥴링하고 실행시키는데 사용된다.
- 평가받는 학생이 서버가 시작된 후 10분마다 실행되도록 스크립트를 설정하는 방법입니다. 스크립트의 올바른 기능이 확인되면 평가 대상 학생은 이 스크립트가 매분 실행되는지 확인해야 합니다. 스크립트가 동적 값으로 올바르게 실행되는지 확인하기 위해 원하는 것은 무엇이든 실행 할 수 있습니다. 마지막으로 평가 대상 학생은 서버가 시작될 때 스크립트를 실행을 중지 해야 하지만 스크립트 자체는 수정하지 않아야 합니다. 이 점을 확인하려면 마지막으로 서버를 다시 시작해야 합니다. 시작시 스크립트가 여전히 같은 위치에 있는지, 해당 권한이 변경되지 않았는지, 수정되지 않았는지 확인해야 합니다. 예상대로 작동하지 않거나 명확하게 설명되지 않는 경우 평가는 여기서 중지됩니다.
    - **`$ crontab -e`**
    - <crontab 기본 문법>
        
        ```cpp
        *** / *  *  *  *  *   [실행할 직업] | wall
           분/시/일/월/요일
        */10 -> 10분마다 실행
        wall -> 모든 터미널에서 메세지를 출력하는 명령어
        요일-> 0: 일요일, 6: 토요일**
        ```
        
    - cron 중지 후, 다시 시작한 다음 중지되었는지 확인
    - **`$ sudo systemctl disable cron` → 껏다 켜도 실행안되게!!!!! 이게 정답**
        
        **`$ service cron stop` →** 중지
        
        **`$ service cron start` →** 시작
